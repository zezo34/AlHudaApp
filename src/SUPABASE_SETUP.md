# ربط تطبيق الهدى بسحابة Supabase — دليل الإعداد الكامل
# AlHudaApp ⇄ Supabase — Full Setup & Go-Live Guide

> **ماذا تغيّر في الكود؟** أصبحت كل البيانات تُقرأ من Supabase وتُخزَّن محلياً على الجهاز (AsyncStorage) كنسخة احتياطية تعمل بدون إنترنت. لا توجد أي بيانات وهمية (mock) في التطبيق بعد الآن:
>
> - `context/AuthContext.js` و `context/CourseContext.js` أعيدت كتابتهما لتعمل مع طبقة بيانات جديدة.
> - `services/supabaseDataService.js` — طبقة البيانات: قراءة (كاش أولاً ثم السيرفر)، كتابة فورية (optimistic) مع طابور مزامنة عند انقطاع الإنترنت، وترحيل تلقائي للبيانات القديمة.
> - `services/offlineStore.js` — الكاش المحلي وطابور العمليات المعلّقة.
> - `services/supabase.js` — إعدادات الاتصال (تُقرأ من `.env`).
> - `supabase/schema.sql` — قاعدة البيانات الجاهزة للنشر.
> - `scripts/seedSupabase.js` — بذر الكورسات والإعدادات وتعيين الأدمن.

---

## ١) ما ستحتاجه (Prerequisites)
- حساب على [supabase.com](https://supabase.com) (مجاني يكفي للبدء).
- المشروع كما هو على جهازك (Expo SDK 54). لا حاجة لأي تثبيت جديد — حزمة `@supabase/supabase-js` موجودة بالفعل في `package.json`.

## ٢) أنشئ مشروع Supabase
1. ادخل supabase.com ← **New project**.
2. سمِّ المشروع (مثلاً `alhudaapp`)، اختر كلمة مرور قاعدة البيانات، واختر المنطقة الأقرب لطلابك (مثلاً Europe Central أو Saudi Arabia إن توفرت).
3. من الشاشة الرئيسية للمشروع انسخ قيمتين:
   - **Project URL** (مثل `https://xxxx.supabase.co`)
   - **API keys ← anon / publishable** (مثل `sb_publishable_...`)

> ملاحظة: التطبيق يحتوي حالياً على قيم افتراضية لمشروعك الحالي داخل `src/services/supabase.js`. لو أنشأت مشروعاً جديداً، ضع قيم المشروع الجديد في `.env` كما في الخطوة التالية.

## ٣) أنشئ ملف البيئة `.env`
في **جذر المشروع** (المجلد الذي يحتوي `App.js` — أي `D:\AlHudaApp`) أنشئ ملفاً باسم `.env`:

```
EXPO_PUBLIC_SUPABASE_URL=https://xxxx.supabase.co
EXPO_PUBLIC_SUPABASE_ANON_KEY=sb_publishable_xxxx
```

ثم **أعد تشغيل الخادم** حتى تُلتقط المتغيرات:

```bash
npx expo start --clear
```

## ٤) شغّل قاعدة البيانات (الأهم!)

### ⭐ الطريقة الأسهل (موصى بها) — ملف واحد يبني ويملأ كل شيء:
1. من لوحة Supabase افتح **SQL Editor**.
2. الصق محتوى ملف **`supabase/setup_all.sql`** كاملاً واضغط **Run** — مرة واحدة فقط.

هذا الملف يقوم بـ ٣ أشياء دفعة واحدة:
- **يحذف الجداول القديمة الفارغة** تلقائياً لو لسه موجودة (الاسكيما القديمة id = uuid) — آمن تماماً لأنها كلها فارغة ومتحقق منها.
- **ينشئ كل الجداول الجديدة** (13 جدولاً) مع الفهارس والـ triggers.
- **يملأ كل البيانات** فوراً: الكورسات الثلاثة + دروسها، الاشتراك، قائمة الإجازات (١٩ نوعاً)، رابط غرفة Google Meet، رقم المحفظة.

> ✅ الملف **آمن لإعادة التشغيل** (idempotent) — تقدّر تشغّله أي عدد من المرات من غير أي ضرر.

### الطريقة البديلة (خطوتان):
1. لو شغّلت النسخة القديمة سابقاً، شغّل أولاً: `DROP SCHEMA public CASCADE; CREATE SCHEMA public;` ثم Run.
2. الصق محتوى ملف `supabase/schema.sql` واضغط **Run** (يبني الجداول فقط)، ثم نفّذ سكربت البذر في الخطوة ٧ لملء البيانات.

> هذا الملف يبني كل الجداول (الطلاب، الكورسات، الدروس، الاختبارات، النتائج، تقارير التسميع، الحصص المباشرة، المدفوعات، الاشتراكات، الإجازات، إشعارات الأولياء، الإعدادات) مع الفهارس والـ triggers. **RLS معطّل** كتسهيل للتطوير كما طلبت سابقاً — راجع القسم الأخير قبل الإطلاق.

## ٥) فعّل تسجيل الدخول بالبريد (مطلوب للأدمن)
1. من Supabase: **Authentication ← Providers ← Email**.
2. فعّل **Enable Sign up** و **Confirm email** (يمكن إيقاف تأكيد البريد أثناء التطوير لتسريع التجربة).

## ٦) أنشئ حساب الأدمن
1. من Supabase: **Authentication ← Users ← Add user**.
2. أنشئ بريداً وكلمة سر (مثال: `admin@alhuda.app` وكلمة قوية).
3. سيُنشئ التطبيق تلقائياً بروفايل لهذا المستخدم (بسبب الـ trigger في السكربت). **لكن** دوره الافتراضي `student` — يجب ترقيته إلى `admin` عبر سكربت البذر:

## ٧) بذر المحتوى وترقية الأدمن
من **جذر المشروع** شغّل:

```bash
node src/scripts/seedSupabase.js --admin-email admin@alhuda.app
```

سيقوم السكربت بـ:
- **فحص الاسكيما أولاً**: لو كانت قاعدة البيانات ما تزال قديمة (id = uuid) سيوقفك برسالة واضحة تطلب تشغيل `schema.sql` — شغّل `DROP SCHEMA public CASCADE; CREATE SCHEMA public;` ثم `schema.sql` ثم أعد تشغيل السكربت.
- إدراج الكورسات الثلاثة + الدروس (المحتوى الذي كان مكتوباً داخل الكود).
- حفظ كل الإعدادات الثابتة في `app_settings`: بيانات الاشتراك، **قائمة الإجازات (١٩ إجازة)**، **رابط غرفة Google Meet**، **رقم المحفظة** — وبهذا لا تبقى أي بيانات ثابتة (mock) داخل الكود؛ التطبيق يقرأها من قاعدة البيانات (مع كاش محلي) وfallback مؤقت فقط.
- ترقية بروفايل الأدمن إلى `role = admin`.

لإضافة طلاب من ملف JSON (اختياري — لو صدّرت بيانات قديمة):
```bash
node src/scripts/seedSupabase.js --admin-email admin@alhuda.app --students-file students.json
```
صيغة الملف: مصفوفة من كائنات الطلاب `[{ "name": "أحمد", "studentId": "STU-101", ... }, ...]`.

> 💡 البيانات القديمة المخزنة على الأجهزة (طلاب، إجازات، تقارير، طلبات دفع...) تُرفع إلى Supabase **تلقائياً** في أول فتح للتطبيق بعد هذا التحديث — لا حاجة لأي خطوة يدوية.

## ٨) جرّب التطبيق
```bash
npx expo start
```
- **الأدمن:** سجّل الدخول من بوابة الإدارة بالبريد وكلمة السر.
- **الطالب/ولي الأمر:** أدخل كود الطالب كما كان من قبل (مثلاً `STU-101`).
- جرّب تشغيل الطائرة (وضع الطيران) مع فتح التطبيق: كل البيانات التي ظهرت من قبل تبقى متاحة لأنها محفوظة في الكاش، وأي تعديلات تُخزّن محلياً وتُرفع للسيرفر تلقائياً عند عودة الإنترنت.

## كيف تعمل المزامنة دون اتصال؟ (Offline-first)
| الحالة | السلوك |
|---|---|
| فتح التطبيق بدون إنترنت | كل شيء يظهر فوراً من الكاش المحلي (AsyncStorage) |
| تعديل/إضافة بدون إنترنت | يُحفظ محلياً فوراً + يُضاف لطابور المزامنة `@alhuda_pending_writes` |
| عودة الإنترنت | الطابور يُفرَّغ تلقائياً عند فتح التطبيق أو بعد أي عملية ناجحة |
| ترقية من النسخة القديمة | تُنقل بيانات `@students_database` و`@course_content` وغيرها إلى Supabase مرة واحدة، وتُحذف مفاتيح النسخة القديمة (مع نسخة احتياطية `__backup`) |

## خريطة البيانات (الوظيفة ⇄ الجدول)
| وظيفة التطبيق | الجدول في Supabase |
|---|---|
| الطلاب / الأولياء / الأدمن | `profiles` (كود الطالب = `student_code`) |
| الكورسات + الوحدات والدروس | `courses` + `lessons` |
| الاختبارات وسؤال الأسبوع | `exams` |
| إجابات الطلاب وتصحيح المعلم | `exam_results` |
| تقارير جلسات التسميع | `recitation_reports` |
| طلبات الإجازة | `leave_requests` |
| إشعارات الأولياء | `parent_notifications` |
| طلبات الدفع اليدوي | `payments` |
| بيانات الباقة والاشتراك | `app_settings` |
| الحصص المباشرة | `live_sessions` |

## ✅ قائمة ما قبل الإطلاق (Go-Live Checklist)
0. **⚠️ احذف حساب الدخول المحلي `admin / admin` قبل الإطلاق!** موجود في `src/context/AuthContext.js` تحت اسم `LOCAL_ADMIN_ACCOUNT` — أي شخص يعرفه يقدر يدخل لوحة التحكم كلها. احذف الكتلة الخاصة به (أو غيّر الباسورد) واعتمد على حساب Supabase فقط.
1. **فعّل تأكيد البريد** في Authentication ← Providers ← Email (Confirm email = ON) للتسجيل الآمن.
2. **فعّل RLS** — قم بإزالة سطور `DISABLE ROW LEVEL SECURITY` من السكربت وأضف سياسات (أمثلة جاهزة في نهاية `schema.sql`). ابدأ بسياسات بسيطة:
   - قراءة `courses`/`lessons` للجميع.
   - قراءة وتعديل `profiles` للمستخدم نفسه أو الأدمن فقط (`auth.uid()::text = id`).
   - `exam_results`/`payments` للطالب صاحبها أو الأدمن.
3. **لا تضع service role key في التطبيق أبداً** — استخدم فقط مفتاح anon/publishable.
4. **غيّر كلمة سر قاعدة البيانات** واحتفظ بها في مدير كلمات سر.
5. **فعّل النسخ الاحتياطي**: Database ← Backups (تتوفر لاحقاً في المشاريع المدفوعة؛ يمكنك أيضاً تصدير يدوي بشكل دوري).
6. **اختبر من جهاز حقيقي بدون إنترنت** قبل النشر.
7. لو أنشأت مشروع Supabase **جديداً**، استبدل القيم الافتراضية في `src/services/supabase.js` بقيم `.env` (أو احذف القيم الافتراضية لمنع تسريب مفتاح قديم).

## 🔧 حل المشاكل الشائعة (Troubleshooting)
| المشكلة | الحل |
|---|---|
| `relation "public.profiles" does not exist` | لم تُشغّل `schema.sql` بعد — راجع الخطوة ٤ |
| لا يمكن دخول الأدمن | تأكد من أنك شغّلت `seedSupabase.js --admin-email` بعد إنشاء المستخدم، وأن البريد/كلمة السر صحيحان، وأن Email auth مفعّل |
| التعديلات لا تظهر على جهاز آخر | تأكد من اتصال الإنترنت؛ التعديلات تُرفع عند أول اتصال ناجح (طابور المزامنة) |
| البيانات القديمة لم تُرحّل | أعد فتح التطبيق مع إنترنت؛ الترحيل يحدث مرة واحدة تلقائياً |
| التطبيق لا يرى `.env` | أعد تشغيل `npx expo start --clear` (Expo يقرأ `.env` عند بدء التشغيل فقط) |
| عند مسح بيانات التطبيق يختفي الكاش | هذا طبيعي: الكاش محلي على الجهاز، والبيانات الأساسية آمنة في Supabase |
